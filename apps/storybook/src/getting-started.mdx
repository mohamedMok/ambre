# Install and use Ambre

Ambre is a set of accessible web components and the tokens that theme them. The components are standard custom elements, so the same tags work in any framework or in plain HTML. A brand is one preset file; the markup never changes.

<div
  style={{
    display: 'flex',
    flexWrap: 'wrap',
    alignItems: 'center',
    gap: '12px',
    margin: '24px 0',
    padding: '32px',
    border: '1px solid var(--amb-color-border-disabled)',
    borderRadius: '16px',
    background: 'var(--amb-color-bg-canvas)',
  }}
>
  <amb-button>Save changes</amb-button>
  <amb-button variant="secondary">Cancel</amb-button>
  <amb-toggle name="sso" checked>Require single sign-on</amb-toggle>
  <amb-badge variant="success">Paid</amb-badge>
</div>

## Packages

| Package | Carries | Entry points |
| --- | --- | --- |
| `@ambre-ds/tokens` | Every `--amb-` variable for light and dark, and the brand presets | `@ambre-ds/tokens/css`, `@ambre-ds/tokens/css/presets`, `@ambre-ds/tokens/scss`, `@ambre-ds/tokens/json` |
| `@ambre-ds/ui` | The core elements: actions, forms, feedback, navigation | `@ambre-ds/ui`, or one element at a time: `@ambre-ds/ui/button` |
| `@ambre-ds/commerce` | Shop compositions built on the core, starting with quantity | `@ambre-ds/commerce` |
| `@ambre-ds/ai` | Conversation compositions: prompt, message, thinking, suggestion | `@ambre-ds/ai` |

Most products need the first two.

## 1. Install

Add the tokens and the library from npm, with the fonts the default brand names:

```bash
npm install @ambre-ds/tokens @ambre-ds/ui
npm install @fontsource/source-sans-3 @fontsource/source-code-pro

# Shop compositions, only if the product needs them
npm install @ambre-ds/commerce
```

The packages share one version. Each release is published from CI with npm provenance.

To contribute or try an unreleased change, build from source with Node 22 and pnpm 12:

```bash
git clone https://github.com/mohamedMok/ambre.git
cd ambre
pnpm install
pnpm build
```

## 2. Load in this order

Fonts, then tokens, then presets, then the library. The tokens must exist before the first element renders.

```js
// 1. Fonts: the faces the theme names
import '@fontsource/source-sans-3/400.css';
import '@fontsource/source-sans-3/600.css';
import '@fontsource/source-code-pro/400.css';

// 2. Tokens: every --amb- variable, light and dark
import '@ambre-ds/tokens/css';

// 3. Presets: only when the product uses data-brand
import '@ambre-ds/tokens/css/presets';

// 4. The library: registers the amb- elements
import '@ambre-ds/ui';
```

Load `Material Symbols Outlined` too if you use `amb-icon` with a `name`.

## 3. Use the elements

Put the visible label in the default slot. It is the accessible name. Form controls join the nearest `<form>` like native ones.

```html
<form action="/sign-in" method="post">
  <amb-text-field name="email" type="email" autocomplete="email" required>Email</amb-text-field>
  <amb-checkbox name="remember">Keep me signed in on this device</amb-checkbox>
  <amb-button type="submit">Sign in</amb-button>
  <amb-link href="/reset">Reset your password</amb-link>
</form>
```

- Use a button to start an action and a link to go somewhere.
- Reach inside a component only through its documented `::part()` names. The internal classes are not an API.

## Events

Every element reports what people do with a DOM event. Listen on the element, or on any ancestor: every event bubbles and crosses the shadow root. The data is in `event.detail`.

```js
document.querySelector('amb-checkbox').addEventListener('change', (event) => {
  console.log(event.detail.checked, event.detail.value);
});
```

| Event | Fired by | `event.detail` |
| --- | --- | --- |
| `change` | checkbox, toggle, checkbox card | `{ checked, value }` |
| `change` | radio, radio card, select, text field, text area, date picker | `{ value }` |
| `change` | range, quantity | `{ value }`, a number |
| `change` | tabs | `{ index }` |
| `toggle` | disclosure, menu | `{ open }` |
| `select` | menu | `{ item, value }` |
| `close` | dialog | `{}` |
| `send`, `stop` | prompt | `{ value }` for send, which is cancelable |
| `input`, `click` | text fields, range, date picker, prompt; button, link, suggestion | native: read `event.target` |

Setting a property from code does not fire an event, as with native elements. No prop starts with `on`.

**Watch them here:** open the **Actions** panel under any story. Every event the component's contract declares is logged as `<tag> <event>`, with its detail.

## 4. Theme and brand

Switch to the dark decisions with `data-theme="dark"` on any ancestor. Pick a brand with `data-brand` on the same element:

```html
<!-- The whole product -->
<html data-brand="atlas" data-theme="light">

<!-- One region in another brand and theme -->
<section data-brand="verdant" data-theme="dark">
  <amb-button>Book an appointment</amb-button>
</section>
```

| Brand | `data-brand` | For |
| --- | --- | --- |
| Ambre | none | Default: warm paper and amber, tactile layers |
| Atlas | `atlas` | Enterprise and data: dense, 36px controls, ink blue |
| Verdant | `verdant` | Public services and health: 18px text, 52px controls, AAA text |
| Noir | `noir` | Luxury and retail: monochrome ink, pill actions, slow motion |
| Press | `press` | Editorial and media: serif, square corners, printed rules |

Use the **Brand** and **Theme** menus in the toolbar above to preview every story in each brand and theme.

To carry your own colours, override semantic variables after the tokens. Never paint a component with a raw colour, and never use a reference token:

```css
:root {
  --amb-color-accent-bg: #0b5cad;
  --amb-color-accent-bg-hover: #094a8c;
  --amb-color-accent-bg-active: #073a6e;
  --amb-color-accent-fg: #0b5cad;
  --amb-color-focus-ring: #0b5cad;
}
```

Check every overridden text colour against its background: 4.5:1 for text, 3:1 for borders and the focus ring.

## 5. Frameworks

- **React**: use the tags directly. Attach listeners on a ref with `addEventListener`, which works for every event in React 18 and 19.
- **Vue** and **Angular** listen with `@change` and `(change)`. **Svelte 5** with `onchange`.
- **Vue**: tell the compiler that `amb-` tags are custom elements: `compilerOptions: { isCustomElement: (tag) => tag.startsWith('amb-') }`.
- **Angular**: add `CUSTOM_ELEMENTS_SCHEMA` to the component that uses them.
- **SvelteKit and other SSR frameworks**: import `@ambre-ds/ui` in `onMount` (or any client-only hook). `customElements` does not exist on the server. Keep the tags and their text in the markup, so the HTML is already there before the elements upgrade.

## How the components are built

- Svelte 5 custom elements with open shadow roots and `ElementInternals` for forms.
- Styles are Sass, organised by ITCSS and named with BEM, compiled once per element into a shared constructable stylesheet.
- Every component has a contract (`contracts/<id>.yaml`): its props, slots, events, accessibility and tokens. CI fails when code and contract drift apart, and checks 40 contrast pairs in every brand and theme.
